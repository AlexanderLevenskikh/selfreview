# Детерминированный приёмочный пилот рабочего процесса

[English](README.md)

Каталог содержит ограниченный заранее зарегистрированный инженерный пилот.
Синтаксическая совместимость, жизненный цикл правил, актуальность источников,
покрытие выборки, применимость diff и сравнение с базой фиксируются
**раздельно**. Текущий протокол включает **17 сценариев**:
исходные 16, одну открыто описанную поправку исходной предпосылки и
дополнительный отрицательный граничный контроль.

Первая улучшенная реализация и финальный интеграционный снимок прошли
все 17 заявленных сценариев. Сравнение, история протокола, точные снимки
кода и ограничения — в [RESULTS.ru.md](RESULTS.ru.md).

## Состав

- `PLAN.md` и `cases.json` — первоначальные 16 сценариев, исходные строки
  примеров и ожидаемые смысловые результаты.
- `preregistered.json` — SHA-256, зафиксированные до улучшенной реализации.
- `ADJUDICATION.md`, `ADJUDICATION-02.md`, два файла в `amendments/` и
  отдельные регистрации — предпусковая исправленная арифметика и новый
  отрицательный контроль. Первоначальные план и примеры не удалены.
- `run.mjs` — текущий адаптер API и runner. Перед каждым запуском сверяет
  зафиксированные хеши и отказывается перезаписывать файл результата.
- `runner-historical-01.mjs` — точные байты оценщика первого исторического
  прогона. Это свидетельство, а не параллельная поддерживаемая реализация.
- `results/historical-01.json` — первый сохранённый прогон на коммите
  `67a42ad980a4b82f8b58c0c9c7e2bbaed19e4fe4`.
- `results/historical-02.json` — исторический прогон с 16 исправленными
  сценариями; `runner-historical-02.mjs` хранит его runner.
- `results/historical-03.json` — исторический прогон 17 исправленных сценариев,
  использованный при текущем сравнении; `runner-historical-03.mjs` хранит runner.
- `results/current-01.json` — первый успешно прошедший снимок улучшенной
  реализации; сохранён без изменения.
- `results/current-02.json` — финальный интеграционный снимок SelfReview
  версии 0.2.0: те же 17 сценариев и тот же runner, что у
  historical-03/current-01.

Другие каталоги оценки и их прежние результаты пилот не менял.

## Запуск из корня репозитория

Для каждого зарегистрированного прогона используйте **новое** имя файла:

~~~sh
node evaluation/workflow/run.mjs --out evaluation/workflow/results/current-next.json
~~~

Исторический сравнительный runner извлекает только собственные
`src/`, `bin/` и `package.json` во временный каталог. Он использует уже
установленные закреплённые зависимости и **не** исполняет код
синтетических проектов:

~~~sh
node evaluation/workflow/run.mjs --historical 67a42ad980a4b82f8b58c0c9c7e2bbaed19e4fe4 --out evaluation/workflow/results/historical-next.json
~~~

Записанный прогон возвращает код 0 только когда **все** объявленные
сценарии пройдены и исходники реализации не менялись во время запуска.
Код 2 означает заявленные пробелы, недоступные функции, неожиданные ошибки
или нестабильный снимок реализации. Историческая версия по замыслу
показывает пробелы нового workflow; они сохраняются как свидетельство,
а не объявляются инфраструктурной ошибкой.

## Первоначальный исторический результат

На исходном коммите main:

| Результат | Сценарии |
| --- | ---: |
| PASS | 4 |
| FAIL | 3 |
| NOT_AVAILABLE | 9 |
| Неожиданные ошибки runner | 0 |

Синтаксис совпал с эквивалентной настройкой нативного ESLint:
пять ожидаемых кортежей находок в A, B/C/D и E, без дополнительных
находок в отрицательных файлах. Неавтоматическое подтверждение,
отдельность условных/manual-требований и ошибка разбора выбранного
файла также соответствовали ожиданиям.

Три сбоя: дубль логической политики из повторных MR-свидетельств,
повторение правила после несвязанного изменения документа и `INCOMPLETE`
для diff только по документации. API статуса источников, состояния
покрытия по проекту и классификации относительно базы тогда
отсутствовали; эти девять сценариев обозначены `NOT_AVAILABLE`.

До улучшенного запуска в оценщике обнаружилась ошибка малой выборки:
20 `const` + 4 `var` означают только **83,33%** при пороге 90%,
поэтому предложение `no-var` правильно не создавалось.
Сценарий недостаточного малого проекта теперь использует 200+4,
а исходные 20+4 сохранены как отдельный контроль отсутствия
предложения. Исторический прогон на 17 исправленных сценариях:
**5 PASS, 3 FAIL, 9 NOT_AVAILABLE, 0 неожиданных ошибок**.
Это явно изменённый протокол, а не переименованный исходный запуск.

## Интерпретация

Сценарии написаны автором, это не слепой benchmark и не выборка реальных
командных MR. Синтаксический контроль использует только эквивалентные
`no-var`, `no-console` и `eqeqeq`. Он не сравнивает посторонние
правила и не утверждает, что SelfReview точнее ESLint.

Экономия времени разработчика, предотвращённые замечания ревьюеров,
качество агента, стоимость инференса, precision/recall на реальных
командных MR, архитектурная корректность и распространение продукта
остаются **NOT_MEASURED**. Записанное время — диагностика, а не
производительный benchmark.

Поздний успешный прогон подтверждает устранение именно этих ошибок
на данных входах. Он не отменяет исторические неудачи и не доказывает,
что из любого проекта можно автоматически вывести соглашения.
