# Разбор workflow-пилота 01 — предпосылка малой выборки

[English](ADJUDICATION.md)

Поправка обнаружена при чтении арифметики заранее зарегистрированного
примера и документированного API покрытия по предложениям
**до любого запуска улучшенной реализации**.

Первоначальный случай `small-contradictory-sample-is-insufficient`
содержал 20 объявлений `const` в большом проекте и 4 `var` в малом.
Совокупная доля 20/24 = **83,33%**, ниже зарегистрированного порога **90%**.
Поэтому discovery **правильно** не выдавал кандидата `no-var`.
Исходный оценщик ошибочно предполагал наличие такого кандидата перед
проверкой покрытия каждого проекта.

Это ошибка **подготовки оценщика**, а не новый дефект реализации.
Исходный смысл приёмки не меняется: если общая конвенция **предложена**,
проект с четырьмя противоположными случаями должен иметь статус
недостаточного покрытия при `minSamples=5`.

## Прозрачная поправка

`amendments/001-sparse-sample.json` меняет **только** входные данные
большого проекта в данном сценарии на 200 объявлений `const`.
Малый проект сохраняет 4 `var`. Совокупная доля становится
200/204 = **98,04%**: статистическое предложение `no-var` появляется,
но собственная выборка малого проекта всё ещё недостаточна.

Ни ожидаемые исходы, ни пороги, ни другие сценарии, ни production-код
не менялись. Новые байты примера зафиксированы и захешированы в
`preregistered-amendment-01.json` **до** первого улучшенного запуска.

Исходные `PLAN.md`, `cases.json`, `preregistered.json`,
`runner-historical-01.mjs` и `results/historical-01.json` сохранены.
Второй исторический запуск использует поправку, чтобы сравнивать старую
и новую реализации на одинаковых данных. Отчёты обязаны указывать свою
регистрацию; первый исторический прогон нельзя задним числом объявлять
исполненным с исправленным примером.
