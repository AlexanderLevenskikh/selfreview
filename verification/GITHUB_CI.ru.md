# Проверка GitHub CI после публикации

[English](GITHUB_CI.md)

Этот документ дополняет первоначальный [отчёт о проверке](../VERIFICATION.ru.md).
Исторический отчёт, синтетические снимки реализации и сырые результаты
относятся к переносимой поставке. Последующие коммиты фиксируют изменения
публикации и описанное ниже исправление Windows.

## Первоначальный прогон на GitHub

[Первый запуск workflow](https://github.com/AlexanderLevenskikh/selfreview/actions/runs/42461719670)
проверял коммит публикации `6734bdfc3291516843abdc898b1ab3750807e1ce`:

| Runner | Node.js | Результат |
| --- | --- | --- |
| Ubuntu | 22 | Тесты и повторение публичного корпуса пройдены |
| Ubuntu | 24 | Тесты и повторение публичного корпуса пройдены |
| Windows | 22.23.4 | 105/107 тестов пройдены; проверки корня Git завершились ошибкой |
| Windows | 24.22.2 | 105/107 тестов пройдены; проверки корня Git завершились ошибкой |

Оба Windows-падения отклонили корневую папку собственного тестового репозитория.
Первоначальная реализация сравнивала **строки абсолютных путей** из Git и Node.js;
на Windows алиасы путей и регистр букв могут различаться даже для одного каталога.
Затронуты тест CLI exact-root и регрессионный тест фильтра чистоты Git.

Исходные журналы сохранены:
[Windows 22](windows-initial/job-128672236468.log) и
[Windows 24](windows-initial/job-128672236871.log).
После падения теста в этих заданиях повторение публичного корпуса не запускалось.

## Исправление

`diffFromGit` теперь спрашивает Git, находится ли рабочая папка в Git-дереве
и пуст ли префикс пути относительно корня репозитория. Принимается только
корень рабочего дерева; вложенный проект по-прежнему отклоняется, поэтому
граница анализа не расширилась. Проверка нормализует CRLF и не сравнивает
Windows-строки абсолютных путей.

После исправления локально на Linux Node.js 24.22.1 прошли все **107 тестов**
без ошибок и пропусков. Журнал:
[linux-after-fix.tap](windows-initial/linux-after-fix.tap). Сам по себе
этот запуск не доказывал успех на Windows.

Добавлен `.gitattributes`, сохраняющий исходные байты эталонного корпуса при
checkout на Windows. Ожидаемые хеши корпуса не менялись.

## Текущее состояние размещённых проверок

Проверяйте workflow для **точного коммита**, а не только название ветки:

- [Workflow организации](https://github.com/levencode-labs/selfreview/actions/workflows/ci.yml).
- [Workflow fork для публикации](https://github.com/AlexanderLevenskikh/selfreview/actions/workflows/ci.yml).

Матрица выполняет `npm ci --ignore-scripts`, `npm test` и повторную проверку
закреплённого публичного корпуса на Ubuntu/Windows × Node.js 22/24.
Нативный Windows-run подтверждает эти автоматические шаги, **но не**
ручной запуск всех примеров PowerShell 5.1 из руководств.

Для версии 0.2.0 успешно прошли [проверки PR #2](https://github.com/levencode-labs/selfreview/actions/runs/42473541119)
и [повторная матрица на main](https://github.com/levencode-labs/selfreview/actions/runs/42473677735):
в каждом прогоне четыре задания завершились успешно. Считайте это
зафиксированным состоянием указанных коммитов, а не гарантией будущих запусков.

## Область манифестов

`SOURCE_MANIFEST.json` остаётся инвентарём переносимой поставки.
`PUBLICATION_MANIFEST.json` описывает **первую** публикацию исходников на
`6734bdfc3291516843abdc898b1ab3750807e1ce`. Оба манифеста не переписывались
ради включения в ранний снимок более поздних файлов. Исправление Windows и этот
отчёт записаны в следующих Git-коммитах. В частности, текущий
`src/review.mjs` отличается от закреплённой синтетической реализации.
