# SelfReview 0.1.0 — результаты проверки

Дата: 8 ноября 2026 года. Исходники, входные корпуса, хеши, сырые результаты и
исторические ошибки находятся в этой поставке. Проверялась локальная реализация
на Linux / Node.js 24.22.1. Нативная Windows-приёмка не выполнялась.

## Вывод

Инструмент пригоден как локальная основа для каталога конвенций, извлечения
проверяемых кандидатов и воспроизводимых JS/TS-проверок по scope. Он точно
различает измеренные синтаксические особенности в выбранных примерах.
Полнота естественно-языковых соглашений, архитектурное качество, корректность
бизнес-логики и сокращение замечаний в реальной команде этим экспериментом
не доказаны.

## Публичные репозитории

Выбор путей и пороги зафиксированы в `evaluation/public/plan.json` до измерения.
Не запускались код, build/test-скрипты или установка зависимостей этих проектов.
Использовались выбранные production-исходники, а не весь каждый репозиторий.

| Репозиторий и точная ревизия | Файлы | Наблюдения | Предложенные кандидаты |
|---|---:|---|---|
| [p-limit](https://github.com/sindresorhus/p-limit/tree/a8a6fbec4e0e866d6d779b10889bb4f5567e70eb) | 1 | 14 const, 2 let, 0 var; 3 строгих сравнения; 9/9 тел со скобками | no-var, require-braces |
| [usehooks-ts](https://github.com/juliencrn/usehooks-ts/tree/61949134144d3690fe9f521260a16c779a6d3797) | 67 | 160 const, 8 let, 0 var; 37 строгих сравнений; 75/82 тела со скобками | no-var, strict-equality, require-braces |
| [underscore](https://github.com/jashkenas/underscore/tree/5c1e5f686f8500af9c9d15614ed60289d6d35d6b) | 161 | 282 var; 71 строгое и 59 нестрогих сравнений, из них 41 с null; 115/230 тел со скобками | Нет кандидатов из нынешнего словаря |

Всего **229/229 выбранных файлов разобраны**, ошибок парсинга нет.
Счётчики объявлений, сравнений и скобок по каждому файлу совпали с отдельно
написанным ESTree-обходом. Для JS использован другой parser, Espree; для TS
использован typescript-eslint, который внутри также опирается на TypeScript.
Поэтому TS-проверка — независимый подсчёт, а не независимая реализация parser.

Из этих результатов нельзя делать вывод «таковы официальные правила проектов».
Для p-limit три сравнения меньше минимальной выборки 5, поэтому гипотеза о
strict equality не выдвинута. Для usehooks-ts семь тел без скобок не скрыты:
кандидат проходит частотный порог 90%, но требует разбора исключений. Для
underscore отсутствие современных кандидатов не означает отсутствие конвенций;
обратные требования вроде «использовать var» пока не входят в discovery-словарь.

Общий рекомендательный слой на underscore дал **235 сырых находок**:
215 по var, 18 по нестрогому сравнению вне null и 2 по размеру функций.
Это демонстрирует потенциальный шум при запуске generic advice без соглашений
проекта. Текстовый CLI группирует повторения по правилу и показывает до трёх
примеров; полный JSON сохраняет все находки. Подтверждённые legacy-исключения
задаются отдельно и имеют приоритет над советами. Автоматического изменения
legacy-кода или утверждения правил не было.

Исходники выбранного корпуса включены вместе с MIT-лицензиями. Полные SHA-256
каждого файла находятся в `evaluation/public/provenance.json`. Данные прогона —
`evaluation/public/results.json`, первоначальный результат сохранён как
`evaluation/public/initial-results.json`. Это небольшая целевая выборка,
не статистический benchmark и не оценка качества чужих библиотек.

### Исправленные проблемы

1. Условие «Production code only» из заголовка документа терялось. Теперь
   сохраняется иерархия разделов; неопределённая или условная применимость
   оставляет prose-правило ручным. Структурированный вариант требует явной
   области действия и последующего подтверждения.
2. Крупный проект с 200 const, 50 strict comparisons и 50 braced bodies
   подавлял маленький с 10 var, 5 loose comparisons и 5 unbraced bodies.
   Частоты были посчитаны верно, но общий scope получал три слишком широкие
   гипотезы. Теперь при достаточной противоположной выборке внутри проекта
   общий learner удерживает их: **0 сохранённых кандидатов, 3 withheld**,
   с именем противоречащего проекта и точными числами.

Прямой низкоуровневый `discoverConventions` по объединённым метрикам всё ещё
измеряет объединённый набор. Защитное решение о нескольких зарегистрированных
проектах принимает `learnScope`; это различие явно отражено в результатах.

### История ошибок оценки сохранена

Исходный baseline имеет exit 1 и `COMPLETED_WITH_IDENTIFIED_GAPS`.
Первый post-fix replay также сохранён с exit 1: один из пяти document assertions
использовал `description.startsWith('Never use var')`. После добавления
заголовка в описание этот селектор перестал находить правильный кандидат.

Отдельное adjudication проверило исходный документ, строку 4 и SHA-256:
кандидат остался manual и сохранил полное исключение. Пять отрицательных
контролей отвергают удалённое условие, исполняемый общий запрет и неверные
path/line/hash. Смысловое требование подтверждено, но сырой неуспешный результат
не переписан. Документ: `evaluation/synthetic/postfix/ADJUDICATION.md`;
данные: `adjudication.json`. Это исправление выбора записи в оценщике,
а не изменение исходного требования или фильтрация неудобного примера.

## Сохранённые ограничения

- Статический компонент на 163 строки с одной основной задачей получает два
  сигнала размера. Это не доказательство плохой архитектуры.
- Компонент на 11 строк, совмещающий UI, оплату, токен, сохранение, навигацию и
  форматирование, получает **0 AST-советов**. Ответственность требует агента или
  человека; этот пропуск не засчитан как успешное покрытие.
- `*.substr` совпадает с пользовательским методом того же имени. Нужна проверка
  типа получателя. Вызов через alias не обнаруживается.
- Обратные legacy-конвенции не синтезируются автоматически.
- Произвольная архитектурная формулировка, runtime-совместимость, business logic,
  типизация и полнота тестов не доказаны синтаксическим обходом.
- Нет измерения экономии времени, уменьшения комментариев коллег или соответствия
  грейду на ваших реальных MR.

## Воспроизведение

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
node .\evaluation\public\run.mjs
```

Публичный replay читает включённые снимки и проверяет их хеши; сеть не нужна
после установки dev-зависимостей. Исторические synthetic runners защищают
существующие результаты от перезаписи. Их код, corpus, snapshots и adjudication
доступны для проверки методики; полная обычная suite запускается через npm test.

CI-файл содержит Ubuntu/Windows × Node 22/24, `fail-fast: false`. В этой сессии
эта удалённая матрица **не запускалась**, поэтому Linux-результаты не выданы за
кроссплатформенную приёмку.
