# История изменений

[English](CHANGELOG.md)

## 0.2.0 — жизненный цикл правил и ежедневное ревью

### Добавлено

- Устойчивые логические идентификаторы правил с учётом scope и отдельным накоплением свидетельств.
- Реестр источников, проверка актуальности, явное обновление, история правил и предварительный просмотр влияния кандидата без изменения каталога.
- История решений и ссылки на возможные новые редакции без автоматического подтверждения или замены действующих правил.
- Раздельные статусы покрытия discovery по проектам: `supported`, `contradicted`, `insufficient`, `unobserved`.
- Контекст задачи для конкретных файлов: поддержка планируемых файлов, проверяемые примеры, точные вызовы CLI и проверка сохранённого контекста.
- Проверка Git по общему предку и индексу, сравнение повторяющихся находок с доверенной базой, разделение существовавших/исправленных нарушений и явная фиксация ухудшенных метрик.
- Отдельный зафиксированный протокол проверки workflow с историческими исходами, открыто описанными исправлениями оценщика и синтаксическими контролями, эквивалентными ESLint.

### Изменено

- Повторные одинаковые замечания к MR и несвязанные правки документа больше не создают конкурирующие копии одной договорённости.
- Пакеты для агента определяют правила по выбранным файлам и связывают отчёт со снимками источников и политики. Сохранённый Git-отчёт сверяется с метаданными снимка, включая изменения только индекса при неизменном рабочем файле.
- Пустой выбор файлов не создаёт команды, которые неявно расширяют ревью до всего проекта. Для контекста и проверки одинаковы границы исключённых файлов, генерации и зависимостей.
- Вопросы для ручного ревью указывают применимые файлы. Изменения только README или удаления могут давать `NOT_APPLICABLE` вместо ошибки анализа.
- Изменение политики или отсутствие её исторической версии приводит к явно обозначенной полной проверке. Несовпадение политики со staged/загруженным состоянием остаётся неполнотой.

### Совместимость и ограничения

- Схема каталога v1 и прежние хеши подтверждений остаются действительными. Новые данные `lifecycle` добавляются к существующим; импорт не сбрасывает ранее принятые решения.
- Обычная проверка затронутых AST-узлов по diff доступна по-прежнему. Опциональная классификация `--new-only` синтаксическая и требует доверенной локальной базы.
- Режимы Git требуют поддержку `--no-lazy-fetch`; отсутствующие объекты вызывают ошибку, а не загрузку из promisor remote. Статическое ревью без Git возможно.
- Бинарные патчи не поддержаны и явно дают неполный результат, включая изменение только бинарных файлов. Проверяемый код и примеры не выполняются.
- Экономия рабочего времени, эффективность агента и уменьшение реальных MR-комментариев пока не измерены. Новый AI API, публикация в registry и автоматическая установка Skill в это изменение не входят.

## 0.1.0 — первоначальное публичное ядро

Каталог политик JS/TS по scope, осторожный импорт документов/замечаний MR, ограниченные AST-проверки, экспорт для ESLint и агентов, руководства на двух языках, сохранённые синтетические и публичные результаты оценки, матрица CI Ubuntu/Windows × Node 22/24.
